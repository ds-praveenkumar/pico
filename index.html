Features

  • Multi-agent delegation — pico plans each task and delegates to worker sub-agents: executor (safe file/shell work) and researcher (web/browser research).
  • Supervision by design — only higher-risk calls (file writes, browsing, non-trivial shell) pause for approval; read-only tools run automatically and are logged.
  • Sandboxed shell — commands run in an isolated sandbox: scrubbed env, enforced CPU/memory/process limits, a timeout, and a command allowlist. pico never deletes files.
  • Growing memory — working (session), episodic (events), and long-term (facts & preferences) memory, plus semantic memory with local vector search — no network needed.
  • Gmail, Calendar & Sheets — read, search, send, and respond via OAuth2 under your explicit approval. Reads run automatically; writes pause for the master.
  • Skills — declarative YAML skills teach pico domain workflows: browser use, gym routines, and expense planning.
  • Auto-compaction — long tool-loop conversations fold into a one-call summary past PICO_COMPACTION_TOKENS, so context never blows up mid-task.
  • Multiple backends — OpenAI-compatible clients for OpenAI, NVIDIA NIM, Cerebras, Groq, and OpenRouter, selected via PROVIDER.
  • Two UIs — a full-screen live dashboard (task plan, tokens, activity, memory, log tail) or a modern Textual interface with history, memory browser, and settings screens.

Quick start

pico is a Python project. Set up a virtualenv, install, configure your provider, and run.

python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # fill in your provider keys
python app.py               # interactive REPL
python app.py "Summarize README.md" -y   # single-shot, auto-approved tools

Providers are selected with PROVIDER in .env — openai, nvidia (default), cerebras, groq, or openrouter. Secrets live only in .env, which is git-ignored.

Architecture

A layered design: import-safe modules, one logical concern per file, and tests for everything.

brain/

Provider-agnostic LLM clients (all OpenAI-compatible) with token-usage tracking, async rich logging, and the three-layer + semantic memory system.

agents/

The pico orchestrator plans and delegates to executor/researcher sub-agents, owns tool dispatch, and exposes plan/step/generate hooks.

tools/

Pure, safe functions the agent loop calls — each with a name and schema entry, confined to the project root, sandboxed, and approval-aware.

The master system prompt in agents/prompts/system.md is the source of truth for behavior. Everything is verified by a mocked test suite — run python -m pytest -q for the full suite.

CLI usage

python app.py                                  # interactive REPL (asks before risky calls)
python app.py "Summarize README.md"            # single-shot; tool calls refused by default
python app.py "Summarize README.md" --yes      # single-shot with auto-approved tools
python app.py --plain "Summarize README.md"    # no full-screen dashboard
python app.py --tui                            # Textual interface (home/history/memory/settings)

Live dashboard — a cyan status header with provider, model, and token counts; the pico answer pane; a task plan beside live per-agent output, token usage, activity, memory sizes, and a captured log tail; and an in-TUI prompt.

TUI — a modern Textual interface: Home, History (h), Memory (m), Settings (s), Help (?), a command palette (Ctrl+k) and an approval modal for higher-risk calls. History is opt-in and redacted.

Memory & growth

pico keeps working memory (session scratchpad), episodic memory (completed tasks), long-term memory (facts and preferences) — all persisted under ~/.pico — plus semantic memory with local vector search, so it recalls by meaning, offline. It reviews its memories before each task and grows itself when it lacks a skill (asking the master first).
